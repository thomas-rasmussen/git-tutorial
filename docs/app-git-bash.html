Appendix A — Git Bash

Git Bash is a Bash emulation used to run Git from the command line. It is part of Git for Windows which is a set of tools for Windows users including both a Bash emulator and a Git installation among other things. Using Git Bash, Windows users can use “git” commands exactly like one would do in Linux and Unix environments. Besides the full set of Git core commands, Git Bash is also packaged with additional basic Bash shell commands that can be useful.

When you run Git Bash, a terminal window will open looking something like this:

user_id$computer_id MINGW64 ~
$

user_id@computer_id is an ID based on the name of the user that is logged in, and the name of the device running Git Bash. The MINGW64 part, is the name of the compiler used to build Git Bash. The tilde (~) at the end of the first line indicates the current working directory. A tilde means that the current working directory is the home directory of the user.

A.1 Terminology

The terms “terminal”, “shell”, “command line”, and “CLI” are often used interchangeably. In most cases this is fine and does not lead to confusion, but they are not synonyms, and understanding the difference makes understanding how to work in text-based environments easier. Furthermore, terms like “prompt” and “output” is often used in connection with working from the terminal.

Terminal

Originally, a terminal was a physical device that you could type commands into, basically a keyboard and a screen. In present times, when we talk about a terminal, we actually mean a terminal emulator. A terminal emulator is a program that emulates a physical terminal. It’s a program that lets you type commands into a window on your computer. It is responsible for drawing text on your screen and processing your keystrokes. And that is basically all it does. Which commands you’re able to use is not determined by the terminal emulator, but by the shell. Likewise, the terminal does not run the commands that you type in, the shell does. The terminal takes your commands, gives them to the shell, the shell then runs the commands and prints any resulting output in the terminal.

Shell

The program that actually runs the commands you type in the terminal is the shell. A shell does a lot of different things, but its main job is to interpret the commands that you type in the terminal and execute them. Which commands you are able to use is determined by what commands that comes with the shell you use.

Shells are often referred to as “REPLs”. REPL stands for:

  • Read

  • Evaluate

  • Print

  • Loop

This means that shells are programs that:

  • Read the commands that you type

  • Evaluate those commands, maybe using other programs on your computer

  • Print the output of those commands

  • Give you a prompt to type another command and repeat

Prompts and outputs

Imagine we have the following session in a terminal:

user_id$computer_id MINGW64 ~
$ echo hello
hello
user_id$computer_id MINGW64 ~
$

The prompt is user_id$computer_id MINGW64 ~ $. The prompt is telling you that the shell is ready to accept a new command. The command that was typed was echo hello, and the output is hello.

After typing the command echo hello and pressing EnterEnter, the shell reads it, evaluates it, prints the output of the command (if any), and then prints a prompt to let you know that it is ready to read another command.

Command line / CLI / working for the terminal

The terms command line and CLI (command-line interface), working from the terminal are also often used interchangeably with the terms terminal and shell to refer to the same thing: Using a program to interact with your computer using text-based commands.

A.2 Using the Bash terminal

The terminal that comes with Git for Windows works fine right out of the box. The only thing that you, as a Windows user, might want to configure, is how to copy and paste text from the terminal. Windows users are used to being able to use Ctrl+cCtrl+c and Ctrl+vCtrl+v to “Copy” and “Paste”, but these shortcuts are not available in Git Bash, since they are reserved for other commands. it is possible to enable “Copy” using Ctrl+Shift+cCtrl+Shift+c and “Paste” using Ctrl+Shift+vCtrl+Shift+v, by right-clicking in the terminal, navigating to Options>Keys, and checking the “Ctrl+Shift+letter shortcuts” box.

The terminal also has many useful shortcut keys. An extensive list can be found here, and below is a short list of the most useful shortcuts:

Description Shortcut
Previous command (Up arrow) Ctrl+p
Next command (Down arrow) Ctrl+n
Copy Ctrl+ins
Paste Shift+ins
Clear the screen Ctrl+l
Interrupt/kill current process (SIGINT) Ctrl+c

Lines starting with “#” are comments, and will not be executed by the shell.

Finally, it is possible to use command-line completion by pressing TabTab. One very useful trick is to use this to auto-complete typing file names in your current working directory. For example, imagine you have to type out “a-very-long-file-name-that-is-tedious-to-type-out.txt”. If you know that no other file in your current directory has a name that starts with “a-very-” you can simply type “a-very-” and hit TabTab, and the terminal will fill in the rest of the name!

A.3 Bash commands

The remainder of this chapter is focused on introducing basic Bash commands that are ubiquitously used in this tutorial to create/list directories and files, edit them, and so on. While you do need to be familiar with these commands to understand the examples and exercises in the tutorial, you don’t necessarily need to use them yourself, if you prefer to use the File Explorer and a text editor to navigate directories, create/edit files, and so on. That being said, it is way faster to use shell commands to do these tasks, at least when you get used to it. If you are unfamiliar with using a terminal, this is also a great opportunity to practice being comfortable doing basic stuff using shell commands, and it will make using Git from the command line feel a lot more natural.

It is not easy to understand1 what Bash shell commands are (or are not) available when using the terminal that comes with Git for Windows , why they are (or are not) available, nor is it straight forward to find documentation on (some of) them. Some commands have documentation that can be accessed by typing help [command-name] or command-name --help in the terminal. More generally speaking, CMD, PowerShell, and Bash command documentation can be found many different places, for example here.

The introduction of the commands is structured around how to do different common tasks, and will focus on very basic uses of the commands, mostly without using any flags (options). The exercises at the end will go a little more in-depth with exploring documentation and using flags with the commands.

Show/change current working directory

The current working directory is the active folder on your computer where your shell runs and perform file operations. When you open your terminal, the current directory is usually your home folder (“~”). We can use the pwd command to print the name of the current working directory, as illustrated below:

user_id$computer_id MINGW64 ~
$ pwd
/c/Users/user_id

To change the current working directory, we can use the cd command. If a path is not provided, the current working directory is changed to the home directory of the user.

user_id$computer_id MINGW64 ~
$ cd /c/test/some-folder
user_id$computer_id MINGW64 /c/test/some-folder
$

If you want to cd into a subdirectory of the current working directory, you don’t have to write the full path, you can just write the name of the subdirectory:

user_id$computer_id MINGW64 ~
$ cd some-sub-dir
user_id$computer_id MINGW64 ~/some-sub-dir
$

Note that forward slashes (/) are used to specify file paths, and that paths can be both on the form C:/path/to/directory and /c/path/to/directory If the file path contains spaces, enclose the file path in (double) quotes.

Git for Windows also comes with shell integration, so you can also change the working directory by navigating to the folder using File Explorer, right click on the folder (shift+right click on Windows 11) and select “Open Git Bash here”.

List files/directories

To list files and directories in the current working directory, you can use the ls command. Imagine your current working directory had two files, file1.txt and file2.txt, and a subdirectory called “sub-dir”. If you used the ls command you would see the following output in the terminal:

user_id$computer_id MINGW64 some-dir
$ cd ls
file1.txt  file2.txt  sub-dir/

Create directory

You can create a new directory in your current working directory by using the mkdir dir-name command, which will create a directory named “dir-name”. If the directory already exists, nothing will happen, i.e. the content of the directory will not be overwritten:

user_id$computer_id MINGW64 ~
# Create directory
$ mkdir new-dir
# Try to create a new directory with the same name
$ mkdir new-dir
mkdir: cannot create directory ‘new-dir’: File exists

Create empty file

To create an empty file in current work directory, use the touch command:

user_id$computer_id MINGW64 ~
$ touch create-empty-file.txt
ls
create-empty-file.txt

Append line to file

To append a string of text as a new line in a file, you can use the echo command together with the >> redirection operators as shown below. If the specified file does not exist, it will be created:

user_id$computer_id MINGW64 ~
$ ls
$ echo "First line" >> file.txt
$ ls
file.txt

Print content of file

To print the content of file in the terminal, use the cat command:

user_id$computer_id MINGW64 ~
$ echo "First line" >> file.txt
$ echo "Second line" >> file.txt
$ cat file.txt
First line
Second line

Move/rename file

To move or rename a file or directory use the mv command. To rename a file/directory, use the form rm old-name new-name and to move a file/directory use the form rm source-file distination-directory:

user_id$computer_id MINGW64 ~
# Create file1.txt
$ touch file1.txt
$ ls
file1.txt
$ # Rename file1.txt
$ mv file1.txt file2.txt
$ ls
file2.txt
$ # Move file to subdirectory
$ mkdir subdir
$ mv file2.txt subdir
$ cd subdir
$ ls
file2.txt

Delete file/directory

You can delete files and directories using the rm command. Note that you must have write permission on the file and the folder where it is stores to be able to delete it. By default, rm does not remove directories. Use the -r flag to remove each directories and their contents, recursively.

user_id$computer_id MINGW64 ~
$ # Create file
$ touch file1.txt
$ ls
file1.txt
$ # Remove file
$ rm file1.txt
$ ls

A.4 Exercises

Exercise 1 - Practice basic commands

In this exercise you will practice basic use of all the commands that have been introduced in this chapter.

1. Change the current working directory to your home directory

TipHint

You are looking for a command that can be used to change directory.

NoteSolution

You can change the current working directory using the cd command. If you just opened your terminal window, the current working directory is probably already set to your home directory, denoted by “~”.

user_id$computer_id MINGW64 ~
$ # If no path is specified, cd sets the current working directory to
$ # the home directory.
$ cd

2. Find the full path to your home directory

It might be unclear to you where exactly your home directory is located. Use a command to print the full path of the current working directory in the terminal.

TipHint

You are looking for a command that can print the current working directory.

NoteSolution

You can use the pwd command to print the full path of the current working directory in the terminal:

user_id$computer_id MINGW64 ~
$ pwd
/c/path/to/your/home-directory

3. Create a new folder

Create a new folder named “git-bash-tests” in your home directory, and cd into the directory.

TipHint

You are looking for a command that can make a directory.

NoteSolution

You can use the mkdir command to make a new directory in your current working directory:

user_id$computer_id MINGW64 ~
$ mkdir git-bash-tests
$ cd git-bash-tests
user_id$computer_id MINGW64 ~/git-bash-test
$

4. Create files

Create two empty files, named “file1.txt” and “file2.txt” in your current working directory. After creating the files, print all files in the current working directory in the terminal.

TipHint

Maybe try to touch the files to create them? To print files in the current working directory, you need some way to list them.

NoteSolution

You can create a file using the touch command:

user_id$computer_id MINGW64 ~/git-bash-test
$ touch file1.txt
$ touch file2.txt
$ ls
file1.txt file2.txt

5. Add lines to files

Add the line “This is file1.txt” to the “file1.txt” file, and the line “This is file2.txt” to the “file2.txt” file. After adding the lines, print the content of the files in the terminal.

TipHint

To add a line to a file, you need some way echo a string and redirect it to a file. To print the content of a file in the terminal, you need a command to concatenate the content to the terminal window.

NoteSolution

You can add a line to a file using the echo command together with >> operator, and you can print the content of the file using cat:

user_id$computer_id MINGW64 ~/git-bash-test
$ echo "This is file1.txt" >> file1.txt
$ echo "This is file2.txt" >> file2.txt
$ cat file1.txt
This is file1.txt
$ cat file2.txt
This is file2.txt

6. Rename and move files

Rename “file1.txt” to “file1-new.txt”, create a subdirectory called “subdirectory” and move “file2.txt” to this subdirectory.

TipHint

There is a single command that can be used to both rename and move files.

NoteSolution

The mv command can be used to both rename and move files:

user_id$computer_id MINGW64 ~/git-bash-test
$ # Rename file1.txt
$ mv file1.txt file1-new.txt
$ # Create subdirectory and move file2.txt
$ mkdir subdirectory
$ mv file2.txt subdirectory
$ # Check that files have been renamed and moved. Note that we are using the
$ # -R flag to list subdirectories recursively
$ ls -R
.:
file1-new.txt subdirectory/

./subdirectory:
file2.txt

7. Cleanup

Complete the exercise by cleaning up: cd back to your home directory and delete the “git-bash-test” folder.

TipHint

You need to use a command to remove the folder. Remember that you are trying to delete a directory, so you might need to use a flag for this.

NoteSolution

The rm command can be used to delete files and directories. Since we want to delete a directory, we need to use the -r flag:

user_id$computer_id MINGW64 ~/git-bash-test
$ # We first need to cd outside the directory we want to delete
$ cd
user_id$computer_id MINGW64 ~
$ rm git-bash-test -r
