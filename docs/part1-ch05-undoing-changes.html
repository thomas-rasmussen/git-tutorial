5  Undoing changes

When working with Git, you will inevitably make mistakes or changes that you later want to undo. For example, you might accidentally stage a file, make unwanted changes to a file, or discover an error in a commit.

Git provides several commands for undoing changes, depending on whether the changes are in the working tree, the staging area, or have already been committed. Some commands allow you to undo changes while preserving your work, whereas others permanently discard changes.

In this chapter, you will learn how to use git commit --amend to modify the most recent commit, git restore to unstage or discard changes, and git reset to undo commits. You will also learn when to use each command and how to avoid accidentally losing your work.

5.1 Amending the current commit

A common mistake is to make an error in the commit log message, or making a premature commit where you forgot to stage all the intended changes. You could fix the mistake by making another commit where you staged the forgotten changes or updated the commit message, but there is a more elegant way to fix these types of issues. You can simply stage the changes you forgot, and use the --amend option with git commit. Let’s illustrate with an example. First, we create a repository with a file named file1.txt which we commit:

$ mkdir ~/example01-undoing-changes
$ cd ~/example01-undoing-changes
$ git init
$ echo "Some contents" > file1.txt
$ git add file1.txt
$ git commit -m "Add file.txt"
$ git log --oneline
1d38fb6 (HEAD -> main) Add file.txt

Now let’s imagine we forgot to add some changes before making the commit. We also notice that we wrote Add file.txt not Add file1.txt in the commit message. We can amend the current commit by making the additional changes, add them to the staging area, and make another commit using the --amend option:

$ echo "More contents" >> file1.txt
$ git add file1.txt
$ git commit --amend -m "Add file1.txt"
$ git log --oneline
32c7f65 (HEAD -> main) Add file1.txt
$ cat file1.txt
Some contents
More contents

Notice how we still only have one commit in the repository, but the commit ID has changed, and the commit message has been updated.

It’s important to understand that what Git is doing here is not so much “amending” the commit, but replacing it with a new commit that will have a new checksum, as also illustrated in the above example. Amending a commit is an example of rewriting the commit history of the Git repository. We will not go into more details on this at this point, but rewriting the commit history should be done with care if you are collaborating with other on a Git repository.

5.2 Restoring the working tree and staging area

The git restore command can be used to restores files in the staging area and working directory with content from a restore source. We can use this command to undo changes we have made in the working tree, unstage changes from the staging area, and also restore earlier versions of files.

Discarding changes in the working tree

Running git restore <file> without any options, restores <file> in the working tree using the content of the <file> in the current commit. That is to say, any unstaged changes in the working tree version of <file> are discarded. Let’s illustrate this with an example. First, we create a repository with a commit of a file named file1.txt:

$ mkdir ~/example02-undoing-changes
$ cd ~/example02-undoing-changes
$ git init
$ echo "Contents of first commit" > file1.txt
$ git add file1.txt
$ git commit -m "Add file1.txt"

Next, we make changes in the working tree but decide, that we do not want those changes anyway. We can use git restore file1.txt to discard them:

$ echo "Unstaged changes in working tree" >> file1.txt
$ cat file1.txt
Contents of first commit
Unstaged changes in working tree
$ git restore file1.txt
$ cat file1.txt
Contents of first commit

After using git restore file1.txt the working tree version of file1.txt has been restore using the version of file1.txt from the current commit.

Warning: You need to be careful when using git restore <file>. You will discard any unstaged changes, and will not be able to recover them.

Unstaging changes

We can unstage changes using git restore --staged <file>. This will restore the staging area with the staging area from the current commit, effectively unstaging changes you have staged. Let’s illustrate this by continuing the previous example:

$ echo "Staged contents" >> file1.txt
$ git add file1.txt
$ git status
On branch main
Changes to be committed:
  (use "git restore --staged ..." to unstage)
        modified:   file1.txt

$ git restore --staged file1.txt
$ git status
On branch main
Changes not staged for commit:
  (use "git add ..." to update what will be committed)
  (use "git restore ..." to discard changes in working directory)
        modified:   file1.txt

no changes added to commit (use "git add" and/or "git commit -a")

What git restore --staged file1.txt has done here, is to restore the version of file1.txt in the staging area, with the version of file1.txt from the current commit.

5.3 git reset - “Undoing” a commit

The git reset command is quite versatile and can also be used instead of the git restore command. For now, we will simply show how to use it to “undo” a commit that we have made, without going into details that uses concepts we have not introduced yet.

Imagine you have the following Git repository where you just commmited some changes that you regret, and now you want to remove them.

$ mkdir ~/example-git-reset
$ cd ~/example-git-reset
$ git init
$ echo "content" > file.txt
$ git add .
$ git commit -m"Add file.txt"
$ echo "content we will regret adding" >> file.text
$ git add .
$ git commit -m"Update file.txt"

We can do this by finding the checksum of the previous commit and “reset” the Git repository to that commit:

$ git log --oneline
246b682 (HEAD -> main) Update file.txt
c481e82 Add file.txt
$ git reset --hard c481e82
HEAD is now at c481e82 Add file.txt
$ git log --oneline
c481e82 (HEAD -> main) Add file.txt

5.4 Summary

In this chapter, you learned how to undo changes and correct mistakes in a Git repository.

  • git commit --amend allows you to modify the most recent commit, for example to correct its commit message or include additional changes.

  • git restore allows you to discard changes in the working tree or unstage changes without discarding them. You can also use it to restore earlier versions of files.

  • git reset allows you to move the current branch back to an earlier commit. Depending on the options used, you can either preserve or discard the changes introduced by subsequent commits.

Some of these operations can permanently discard changes, while others modify the commit history. You should therefore use them carefully, particularly when working with commits that have already been shared with others.

Exercise 1 - Amend a commit

In this Exercise we will practice amending a commit. Run the following code to set-up a Git repository with a commit we want to amend:

$ mkdir ~/ex-amend
$ cd ~/ex-amend
$ git init
$ echo "content of file_a" > file_a.txt
$ echo "content of file_b" > file_b.txt
$ echo "content of file_c" > file_c.txt
$ git add file_a.txt
$ git commit -m"Add file_a.txt"

In the Git repository created by these commands, we have made a commit adding file_a.txt to the repository, but we forgot to add file_b.txt and file_c.txt!

1. Find the checksum of the commit1.

NoteSolution

You can use the git log command to see the checksum of the commit. You could also additionally use the --oneline option to get a nice one-line output with a short version of the checksum:

$ git log --oneline
712d2c6 (HEAD -> main) Add file_a.txt

2. Amend the commit by adding file_b.txt and file_c.txt. “Forget” to update the commit message.

NoteSolution
You can use the --no-edit option to tell Git to use reuse the original commit message: 
$ git add file_b.txt file_c.txt
$ git commit --amend --no-edit

Alternatively, you can omit the --no-edit option, and simply keep the current commit message that Git opens in a text editor.

3. Look at the commit checksum again. Has it changed? Why?

NoteSolution 
$ git log --oneline
0ef247d (HEAD -> main) Add file_a.txt

The checksum has changed. The reason for this is that Git has amended the commit by replacing it with a new commit. This new commit does not have the same content, so the checksum is different.

4. Amend the commit again to update the commit message we “forgot” to update in the previous amended commit.

NoteSolution 
$ git commit --amend -m"Add file_a.txt, file_b.txt, and file_c.txt"

Here we use the optional -m option to specify the commit message directly in the command so that we don’t have to type it in the text editor Git would otherwise open.

5. Look at the commit checksum again. Has it changed? Why?

NoteSolution 
$ git log --oneline
cade118 (HEAD -> main) Add file_a.txt, file_b.txt, and file_c.txt

The checksum has changed again. Again, the commit has been replaced by a new commit where we have updated the commit message. Since the commit message is part of the the commit that has been checksummed, the checksum has changed.

Exercise 2 - Using git restore

Run the following commands to set-up a Git repository for the exercise.

$ mkdir ~/ex-git-restore
$ cd ~/ex-git-restore
$ git init
$ echo "file_a content" > file_a.txt
$ echo "file_b content" > file_b.txt
$ git add . # Add all files
$ git commit -m"Add file_a.txt and file_b.txt"
$ echo "more content" >> file_a.txt
$ echo "more content" >> file_b.txt
$ git add .

Here we have created a Git repository where we have committed two files, then made changes to both files and added them to the index.

1. Unstage file_b.txt and commit file_a.txt.

We were too fast on the trigger. We actually don’t want to commit the changes to both files at the same time. Unstage file_b.txt and commit only file_a.txt.

NoteSolution 
$ git restore --staged file_b.txt
$ git commit -m"Update file_a.txt"

2. Unmodify file_b.txt

Upon further introspection, we decide that we do not want to commit the changes we have made to file_b.txt after all. Unmodify file_b.txt, ie restore the working directory to look like it did in the previous commit.

NoteSolution 
$ git restore file_b.txt
$ git status
On branch main
nothing to commit, working tree clean
$ cat file_b.txt
file_b content

5.6 Exercise 3 - “Undo” commits

Run the following commands to set-up a Git repository:

$ mkdir ~/ex-undo-commit
$ cd ~/ex-undo-commit
$ git init
$ echo "content" > file.txt
$ git add .
$ git commit -m"Add file.txt"
$ echo "more content" >> file.txt
$ git add .
$ git commit -m"Update file.txt"
$ echo "even more content" >> file.txt
$ git add .
$ git commit -m"Update file.txt again"

Here, we have added a file, file.txt, and made changes to it in two commits. At this point we realize that we do not want to make these changes to the file after all.

“Undo” the last two commits to restore the file to the original state before we started making changes to it.

NoteSolution

We can use the `git reset`` command to reset the Git repository to the state before we started making changes to file.txt

$ git log --oneline
2cd5429 (HEAD -> main) Update file.txt again
1836bbe Update file.txt
4387462 Add file.txt
$ git reset --hard 4387462
$ git log --oneline
4387462 (HEAD -> main) Add file.txt
